Device::read_event originally returned Option<DeviceEvent>, collapsing two different situations into None: the fd is drained (EAGAIN) versus a raw event was consumed but maps to no DeviceEvent (Linux key auto-repeat value==2, REL_X/REL_Y accumulation into pending_rel_*, EV_SYN with nothing pending, unmapped extended keycodes; on macOS cgkey_to_keyd_code returning None).

The daemon drained with `while let Some(ev) = dev.read_event()`, so it STOPPED draining on the first ignored event and waited for the next poll(). Level-triggered poll means it always recovers - so this never hangs and never loses an event, which is exactly why it went unnoticed. The cost is a full poll() round trip per ignored event: a mouse or trackpad streaming REL_X/REL_Y pays one syscall per axis sample.

Fix: a three-way `ReadResult { Event(DeviceEvent), Ignored, Idle }`, with callers looping and continue-ing on Ignored. Gotcha for anyone touching this again: Removed stays a DeviceEvent variant rather than becoming a ReadResult variant, so the daemon's existing `break` on device removal is untouched.

General lesson: Option<T> as a read-loop terminator is wrong whenever the producer has a third state. Reach for an explicit enum the moment "nothing to report" and "nothing left" diverge.
