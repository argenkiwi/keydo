When adding a CI gate (ci.yml), the plan assumed cargo fmt --check would only need to fix a small drift in config.rs. Actually running cargo fmt reformats 29 of 30 source files (+6619/-1315 lines) — most of it exploding hand-formatted dense data tables (e.g. the 256-entry KEYCODE_TABLE in keys.rs, one line per entry with a trailing comment) into 4+ lines per entry, because default rustfmt wraps struct literals once the line (including the trailing comment) exceeds max_width.

Decision (user chose, given three options): do not gate CI on cargo fmt --check at all; keep the codebase's existing hand-formatted style as-is, gate only on clippy -D warnings + cargo test. Rejected alternatives: (a) accept the full reformat as a dedicated commit — makes git blame/history noisier and permanently degrades scannability of the keycode/unicode tables; (b) #[rustfmt::skip] just the dense tables — still leaves an open question of what to do with the rest of the reformat diff, more fragile long-term.

General lesson: before assuming a fmt/lint gate is a small mechanical add, actually run the full check (not head-truncated) — a partial view of a formatter's diff can badly understate its blast radius, especially in codebases with deliberately dense, hand-aligned data tables.
