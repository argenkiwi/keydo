Diagnosis of "fumbol layer remained active after releasing all keys" under the kenkyo keyd/default.conf: the config defines 7 chords resolving to oneshot combos containing fumbol (v+m, d+v, x+v, d+x+v, k+m, dot+m, k+dot+m). Any two of those keys pressed within the default 50ms chord_interkey_timeout — including an ordinary typing roll (v down, m down 30ms later) — fires the chord; on release the oneshot latches fumbol (active=1, oneshot_depth=1) and, because the config sets no [global] oneshot_timeout, it stays active FOREVER while idle. This is faithful keyd semantics (oneshot_latch cleared only by the next keysequence press), not a keydo state-machine bug: a 5000-run fuzz found no sequence leaving a layer active after a subsequent keypress. The latch also poisons the next interaction: with fumbol latched, space resolves in fumbol (space = overloadt2(fumbol,...) there, not extend), so attempted extend-nav emits numbers (verified: space+j -> 7) before the latch clears. Mitigations: set oneshot_timeout in [global], and/or raise/remove the accidental chords. Related keydo bug found during the same investigation: [[20260713215804]].
