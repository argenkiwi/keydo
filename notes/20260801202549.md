Implemented a reliability pass targeting the recurring index-space-aliasing bug class (see 20260713215804, 20260801190303/192630). Added: (1) .github/workflows/ci.yml running cargo clippy -D warnings + cargo test on every push/PR (ubuntu-latest only — the hot path has no platform #[cfg] gates, so Linux fully covers it; release.yml stays release-only). (2) debug_assert! at every silent-drop site the historical bugs share a class with: cache_set sentinel check, cache/timeout/chord-queue/overload-queue overflow, and a new Keyboard::new layer-count check. (3) proptest dev-dependency with 3 fuzz configs mirroring the two historical bug shapes plus a MAX_LAYERS-boundary config. (4) log::trace! at all six hot-path transition points (layer activate/deactivate, chord resolve/abort/drop, cache insert/evict/full, timeout schedule/fire/drop), gated via logs release_max_level_info feature so it costs nothing in release (verified via strings on the release binary: 0 trace-string occurrences vs 5 in debug). (5) Fixed KeydoError::ConfigSyntax Display to show the line number (file was always empty — ParseCtx::current_file is never populated in practice, confirmed by grep). (6) Migrated diagnostic eprintln!s in daemon.rs to log::, keeping the panic-sequence exit message as eprintln! since it must be visible unconditionally.

Non-obvious gap found and fixed: config_parse_string (used by every test and now every proptest) never calls config_validate::validate() — only file-loading config_parse does. So MAX_LAYERS was structurally unchecked on that path; added a debug_assert in Keyboard::new plus a permanent regression test.

Also discovered: every parsed config silently gets 5 built-in modifier layers (control/shift/alt/meta/altgr) added on top of user-declared ones in config_parse_string (config_impl.rs) — tripped up the MAX_LAYERS-boundary proptest config until accounted for (needed n = MAX_LAYERS - 6, not MAX_LAYERS - 1).
