keyd C semantics: on key-down the cache entry is stored with .layer = 0 (keyboard.c:1255); ONLY activate_layer() sets ce->layer to a real index, so ce->layer means "this key is currently holding that layer active". keydo src/keyboard_impl/dispatch.rs:95 deviates: it stores the descriptor-lookup layer, so EVERY key pressed while e.g. extend is active carries layer==extend. Op::Swap searches the cache for ce.layer == dl (actions.rs:117-131) and therefore hijacks the first arbitrary entry in slot order (often the swap key itself or a held nav key) instead of the layer-holding key. Consequences (fuzz-verified, 10/5000 random sequences): hijacked key's real release action is lost -> output key stuck down forever (left/delete/backspace); extend active-count underflows on the real holder's release (debug_assert panic in debug builds, layer.rs:39); swap() dies when the wrong key is released. Related: the key-up path (dispatch.rs:99) passes entry.layer as the descriptor layer where keyd passes ce->dl (keyboard.c:1265). Fix both together: store layer: 0 on press, pass entry.dl on release. Minimal 6-event repro + fuzzer preserved in scratchpad diag_fumbol.rs.
