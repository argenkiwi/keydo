Bug: holding a home-row-mod (e.g. d = overloadi(d, timeout(overloadt2(shift,d,200),500,d),150)) then tapping an unrelated chord (comma+dot = enter) produced no output at all instead of shift+enter.

Root cause: process_event checks handle_chord before handle_pending_overload. When a chord resolves (resolve_chord assigns an active_chords[slot] and recursively calls process_event(chord_code,1,..) for the synthetic press), that press can get intercepted and swallowed into an unrelated, already-pending OverloadState.queue if a pending_overload happens to be live at that moment (handle_pending_overload's resolve conditions all require pressed==0, so a press just gets enqueued, never dispatched/cached). Meanwhile handle_chord's physical-key release-tracking block (top of handle_chord) cleared active_chords[i].active = 0 purely from real-key release counting (nremaining==0), independent of whether the synthetic press had ever actually reached resolve_descriptor/cache_set. By the time the deferred queue replayed (once the unrelated overload resolved), resolve_descriptor(chord_code) found the slot already zeroed and fell through to an unbound per-layer lookup -- the chord action was permanently lost.

Fix: stop clearing active_chords[i].active in chord.rs's release-tracking block. Instead free it in dispatch.rs, in the same cache_get-based release branch every other keycode already uses to clear its cache entry -- i.e. anchor the slot's lifetime to the cache lifecycle/actual dispatch, not to physical-key-release counting. No new struct fields, no KeyEvent/queue shape changes needed; resolve_chord and resolve_descriptor's happy path are untouched. Added chord_slot(code) -> Option<usize> helper in dispatch.rs shared by resolve_descriptor and the new release-clear site.

This is the third bug in the chord <-> pending_overload interaction family on this branch, and the mirror image of the chord_suppressed fix (1db135f): that one stopped an overload-deferred replay from re-entering chord disambiguation; this one stops a chord's own in-flight resolution from being invalidated by an unrelated overload's queue/slot-lifecycle interaction. Also incidentally fixes a second latent bug: under the old code a freed-too-early slot could be handed to a brand new unrelated chord match while the old occupant's deferred press/release were still in flight, corrupting the descriptor before replay.

Regression test: test_chord_resolution_survives_unrelated_pending_overload_deferral in src/test_io.rs.
