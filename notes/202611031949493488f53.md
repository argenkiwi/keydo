Op::Command spawns /bin/sh and drops the Child without waiting, which used to leave one zombie per invocation. Daemon::run now sets SIGCHLD to SIG_IGN so the kernel auto-reaps. Gotcha: an ignored SIGCHLD survives exec, so user commands that wait on their own children would get ECHILD; actions.rs uses CommandExt::pre_exec to reset SIGCHLD to SIG_DFL in the child. Do not add .status()/.output()/.wait() calls inside the daemon process: with SIGCHLD ignored they fail with ECHILD. install.rs is fine because it runs as a separate CLI process.
