Op::Command spawns /bin/sh and drops the Child without waiting, which used to leave one zombie per invocation. The daemon's unix loop now calls reap_children() (waitpid(-1, NULL, WNOHANG) until it returns <= 0) once per iteration, so a finished child is reaped on the next wake-up. SIGCHLD=SIG_IGN was tried and rejected: std's Command::spawn calls waitpid on the child after a failed exec and asserts that it succeeds, so with SIGCHLD ignored (ECHILD) the daemon panics. Resetting the disposition in the child needs pre_exec, which also forces a full fork() instead of posix_spawn on the realtime, mlockall'd input thread. Don't add pre_exec to the Command spawn for the same reason. Commands still inherit SCHED_FIFO on Linux; that is a known open issue.
